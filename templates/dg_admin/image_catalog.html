Image Catalog · hard-coded images

How it works
  1. Add the category / product in the admin as usual (name → slug is created automatically).
  2. Put the image files in the project at the path shown below, named by slug.
  3. Commit and deploy. The site picks the files up by itself — no upload, no database field.

Category cover → static/catalog/<category>/_cover.webp · Product images → static/catalog/<category>/<product>/1.webp, 2.webp … (1 = main image) · One-image shortcut → static/catalog/<category>/<product>.webp
Colour images → static/catalog/<category>/<product>/<colour>/1.webp, 2.webp, 3.webp (aim for {{ images_per_colour }} per colour)
Size: products — {{ image_size_hint }} · category cover — {{ cover_size_hint }}.
What exists (categories, products, colours) is listed in products/catalog_data.py; python manage.py sync_catalog loads it into the database (runs on every deploy).
An image uploaded through the admin always overrides the hard-coded one, and products added in the admin sit alongside the hard-coded ones. Customer customization uploads and the "preview shapes" editor still use the database.
